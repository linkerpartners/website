# 배포 가이드

사이트는 빌드된 정적 파일이라 어떤 정적 호스팅(Cloudflare Pages · Netlify · Vercel · S3 등)에도 올릴 수 있어요.

## 1. 올리기 전에

```
cd tools/build
npm install        # 처음 한 번
npm run build      # 페이지 27개 · sitemap.xml · robots.txt · _headers 다시 만들기
```

- `tools/build/site.json`의 **`url`을 실제 도메인으로** 바꾸고 빌드하세요(canonical · hreflang · sitemap이 이 주소로 만들어져요). 공유 이미지(1200×630)가 생기면 `ogImage`에 파일 경로(예: `assets/og.png`)를 적으면 돼요.
- 문구 · 가격 · 연락처를 바꿨다면 `i18n/*.json` · `assets/js/config.js`를 고치고, `src/` 또는 번역을 고쳤을 때만 빌드가 필요해요.

## 2. 올릴 것 · 올리지 않을 것

| 올림 | 올리지 않음 |
|---|---|
| `index.html` `about.html` `services.html` `pricing.html` `cases.html` `insights.html` `contact.html` `privacy.html` `terms.html` `404.html` | `src/` (원본. 올려도 동작에는 무관) |
| `ja/` `en/` | `design-system.html` · `DESIGN.md` · `README.md` (내부 문서. 올리면 안 되는 건 아니지만 검색에 노출돼요) |
| `assets/` `data/` `i18n/` | `docs/` (참고 사이트 실측 원본 포함, 저작권 소지) |
| `sitemap.xml` `robots.txt` `_headers` | `tools/` (로고 생성기 · 빌드 · `node_modules`) |
| | `.agents` `.taste-skill` `skills-lock.json` (도구 설정) |

`design-system.html`은 `noindex`이고 `robots.txt`에서도 막아 두었어요.

## 3. 보안 · 캐시 헤더 (`_headers`)

빌드가 `_headers`를 만들어요(Netlify · Cloudflare Pages 형식. 올리면 바로 적용). 다른 호스팅이면 같은 값을 그곳의 헤더 설정에 옮기세요.

- **`Content-Security-Policy`**: 자기 도메인의 스크립트 · 글꼴 · 이미지만 허용. 예외는 환율 API(`api.frankfurter.dev`)와 첫 화면의 인라인 스크립트 1개(해시로 허용)뿐이에요. 이 스크립트를 고치면 빌드가 해시를 다시 계산해요.
- `X-Content-Type-Options` · `X-Frame-Options` · `Referrer-Policy` · `Permissions-Policy`.
- **캐시**: 글꼴은 1년(`immutable`), 로고 30일, CSS · JS · 번역 · 사례 데이터는 1시간, HTML은 매번 확인(`must-revalidate`). CSS · JS 파일 이름에 버전이 없어서 길게 두지 않았어요.
- 문의 폼 서버를 붙이면(`contact.js`의 `send()`) `connect-src`와 `form-action`에 그 주소를 더해야 해요(`tools/build/build.cjs`의 `csp`).
- 분석 도구(Google Analytics 등)를 쓰면 `script-src` · `connect-src`에 그 도메인을 더하고 쿠키 안내가 필요해요.

## 4. 404 페이지

`404.html`은 한국어 · 일본어 · 영어를 한 화면에 보여 주는 정적 페이지예요. 대부분의 호스팅이 없는 주소에서 자동으로 이 파일을 보여 줘요(경로는 모두 맨 위 `/` 기준).

## 5. 올린 뒤 확인

- 한국어 `/`, 일본어 `/ja/`, 영어 `/en/`이 모두 열리는지, 언어 단추로 같은 페이지로 이동하는지
- `https://도메인/sitemap.xml`과 `robots.txt`
- 구글 서치 콘솔 · 네이버 서치어드바이저에 `sitemap.xml` 등록
- 브라우저 개발자 도구 콘솔에 `Content Security Policy` 오류가 없는지
- iPhone Safari · Android Chrome에서 첫 화면 · 메뉴 · 사례 상세의 부드러움

## 6. GitHub Pages로 올리기 (linkerpartners.com)

저장소에 준비된 것: `CNAME`(도메인) · `.nojekyll` · `.gitignore` · `.github/workflows/pages.yml`(push하면 빌드 → 필요한 파일만 배포). GitHub Pages는 `_headers`를 읽지 않아서, 빌드가 각 페이지 `<head>`에 같은 보안 정책(CSP)을 meta로 넣어요(`frame-ancestors`만 meta에서 무시되어 빠짐).

**공개(Public) 저장소여야 무료예요.** 비공개로 두려면 GitHub Pro가 필요해요. 공개해도 올라가는 것은 사이트 파일과 문서뿐이고(키 · 비밀번호 없음), `docs/reference` · 내부 보고서는 `.gitignore`로 제외돼 있어요.

### 처음 한 번
1. GitHub에서 새 저장소를 **Public**으로 만들기(README · .gitignore · 라이선스는 추가하지 않고 빈 저장소로).
2. 이 폴더에서(`git init`은 이미 되어 있음) `git remote add origin https://github.com/<소유자>/<저장소>.git` → `git push -u origin main`.
3. 저장소 Settings → **Pages** → Build and deployment → Source를 **GitHub Actions**로.
4. Actions 탭에서 "Deploy to GitHub Pages"가 초록색(성공)이 되면 `https://<소유자>.github.io/<저장소>/`에서 확인할 수 있어요(하위 주소라 404 페이지 이미지는 안 맞아도 정상, 도메인 연결 뒤에는 맞아요).
5. 도메인 연결: 도메인 관리(DNS)에서 루트(`@`)의 **A 레코드**를 `185.199.108.153` · `185.199.109.153` · `185.199.110.153` · `185.199.111.153` 네 개로(기존 A · AAAA 레코드는 삭제), `www`는 **CNAME** → `<소유자>.github.io`. **메일(MX) · 메일 인증(TXT) 레코드는 그대로 두세요.**
6. 저장소 Settings → Pages → Custom domain에 `linkerpartners.com` 입력 → "DNS check successful" 뒤 **Enforce HTTPS** 체크(인증서 발급에 몇 분~하루).
7. 구글 서치 콘솔 · 네이버 서치어드바이저에 `https://linkerpartners.com/sitemap.xml` 등록.

### 그다음부터
`src/` · `i18n/` · `assets/` 등을 고쳐 `main`에 push하면 Actions가 `npm run build`를 실행하고 1~2분 안에 사이트에 반영돼요(로컬에서 따로 빌드하지 않아도 되지만, 로컬 확인용으로는 `tools/build`의 `npm run build`를 쓰세요).
